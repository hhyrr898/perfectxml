2024 年，PerfectXML 中文版重启了 411 目录项目，旨在恢复自 2000 年前后起家的 XML 资料站因多次迁移而散落的核心内容。该目录并非教程合集，而是一个按规范主题编排、可供逐条查证的基础知识索引，是开发者快速参考的权威来源。

本文为解决开发者查询 XML 基础规范时面临的资料分散、检索困难问题而写。阅读后，你将不仅能高效利用该目录快速定位所需信息，还能理解其内容收录原则与社区维护方式，为后续参与贡献打下基础。

我参与的第一批整理工作，是把旧站里关于 XML 1.0、Namespaces、XSLT 1.0 的零散页面按主题重新归位。旧页面里不少写法还停留在 2001 年前后的工具语境，比如默认读者都在用某种特定的解析器，这些表述现在会被改写为与实现无关的描述。

411 目录不是规范全文镜像，也不是标准组织文档的翻译。每个条目回答一个具体问题，例如某个属性允不允许出现、某个转义序列在 JSON 字符串里是否合法，然后指向以官方规范为准的核对方向。

## 收录范围与版本口径

目录按四个分区组织：核心语法、数据交换格式、转换与查询、工具与校验。收录的版本口径比较保守，只收已经稳定多年、行为不再变动的基础版本，避免读者被草案改动牵着走。

| 分区 | 代表条目 | 版本口径 |
| --- | --- | --- |
| 核心语法 | 元素与属性、字符引用、CDATA | XML 1.0（第五版，2008 年） |
| 数据交换格式 | 对象与数组、字符串转义、数字表示 | JSON（RFC 8259，2017 年） |
| 转换与查询 | 模板匹配、XPath 轴、序列 | XSLT 1.0、XPath 1.0（1999 年） |
| 工具与校验 | 良构性检查、模式校验、缩进风格 | 以官方规范为准 |

YAML 部分只收 1.2 的基础写法，因为 1.1 与 1.2 在布尔值和八进制写法上的差异，是实际配置文件出错的高频原因。条目里会明确写出两版的差别，不给出跨版本通用的断言。

我自己最常翻的是核心语法分区里的字符引用条目。旧站只列了五个预定义实体，新版补了一句提醒：数字引用在 XML 与 JSON 中处理方式不同，跨格式复制粘贴时要留意。

## 条目怎么维护

维护流程由三条约束固定下来，所有条目都走同一套。

1. 提出条目时先写明它要回答的一个具体问题，一句话说不清就拆成两条。
2. 初稿必须标注所依据的版本或年份，没有明确出处的表述不进入正文。
3. 校对环节做两件事：核对示例能否被最小化复现，检查是否存在把某个库的行为当成规范行为的写法。
4. 合并前由第二位编辑独立复核同一问题，两份结论不一致时条目挂起，直到能指向规范原文。

条目页脚保留修订时间与修订原因，改动记录不删除，只追加。这样当读者发现某个说法变了，能看到变的原因，而不是只看到结果。

维护上还有一条内部约定：任何涉及实现差异的内容，只描述差异本身，不推荐具体产品。这条约定让不少条目在十年尺度上仍然可用，也让编辑少了很多更新负担。

## 开发者怎么用

411 目录的定位是随手查，不是从头读。推荐按下面四个步骤使用。

1. 先定位分区，再定位条目标题。标题尽量写成问题式，例如 CDATA 里能不能出现结束标记，减少在列表里反复点开。
2. 看条目顶部的版本标签，确认你手上的解析器或库对应的规范版本与条目一致，不一致就先看差异段落。
3. 把条目里的最小示例复制到本地跑一次，确认输出符合预期，再放回业务代码。
4. 条目末尾的核对方向用来做最终确认，涉及边界行为时以官方规范为准。

我在带新同事时只交代一件事：查 411 目录时先读版本标签，再读正文。很多人卡住不是因为不懂语法，而是拿 JSON 的字符串转义规则去解释 XML 的属性值，两边对反斜杠的处理完全不同。

目录不提供在线校验服务，也不承诺替代规范阅读。它更像一张标注了出处的地图，帮你在最短时间内知道该去规范哪一节确认。

## 常见问题

### 411 目录收不收最新的格式草案？

不收。只收已经稳定多年、行为不再变动的基础版本。草案类内容变化快，条目维护成本高，也容易误导读者。需要跟踪草案时，以官方规范为准。

### 条目里的示例能直接用于生产吗？

示例追求最小化和可复现，目的是说明一个语法点，没有考虑命名、校验和错误处理。放进项目前请按自己的场景补全，尤其是命名空间声明和字符编码声明。

### 为什么有的条目没写具体库名？

因为库的行为会随版本变化，而规范条文相对稳定。条目只描述规范层面的差异，把选择权留给读者和团队。遇到库行为与条目描述不符时，先确认库实现的规范版本。

### 发现条目写错了怎么办？

条目页脚有修订记录入口，说明问题所在位置和你依据的规范章节即可。编辑会先核对版本口径，再决定是修正还是挂起。改动会追加在修订记录里，不覆盖历史。
